# Продвинутое обучение

Этап 6 замыкает цикл «материал → самостоятельная попытка → проверяемая обратная связь» внутри приложения.

## Видео и тесты

Видео воспроизводится через нативный Expo Video с системными controls и полноэкранным режимом. CMS принимает только прямой HTTPS URL к кроссплатформенному MP4; страницы видеохостингов нужно сначала преобразовать в разрешённый медиапоток. Для production источник должен иметь законные права на распространение и подходящие CORS/range-заголовки. Позиция кешируется на устройстве, сохраняется при переходе приложения в background и после входа синхронизируется с аккаунтом. Неотправленный offline-прогресс повторно загружается при следующем открытии видео. 90% длительности считаются завершённым просмотром, и этот признак не сбрасывается при последующей синхронизации.

Web-export использует SPA-режим с fallback на `index.html`, поэтому deep link `/video/<cms-id>` работает и для материалов, созданных после сборки. Хостинг должен применять это rewrite; совместимое правило для Netlify/Cloudflare Pages включено в `public/_redirects`.

Публичный content API отдаёт формулировки, номер ревизии и варианты квиза, но скрывает `correctIndex` и `explanation`. Проверка выполняется backend только при совпадении `contentVersion`; объяснение возвращается только вместе с результатом попытки. Локальный progress позволяет продолжить просмотр offline, но отправка квиза требует аккаунта и сети. Позиция синхронизируется монотонно внутри конкретной ревизии, свежая ненулевая длительность заменяет старые метаданные, а позиция ограничивается концом файла. Новая опубликованная ревизия получает отдельный кеш и начинает просмотр, completion и лучший результат квиза заново.

## Проверка JavaScript

Runner по умолчанию выключен. Для локальной среды:

```bash
docker pull node:24-alpine
# server/.env
CODE_RUNNER_ENABLED=true
CODE_RUNNER_IMAGE=node:24-alpine
```

Поддерживаются синхронные JavaScript-функции без сторонних пакетов. CMS хранит допустимое имя локальной функции `entrypoint`, JSON-аргументы и ожидаемый JSON-результат; публичный API скрывает тест-кейсы. Harness заранее создаёт локальную привязку entrypoint, поэтому пустое решение не может пройти тесты вызовом одноимённой глобальной функции среды выполнения.

Каждый запуск создаёт новый контейнер со следующими ограничениями:

- сеть отключена, файловая система read-only, root/capabilities отсутствуют;
- 64 MB памяти, 0.5 CPU, до 32 процессов и host timeout 6 секунд;
- образ никогда не скачивается во время запроса (`--pull=never`);
- код передаётся через stdin, а Docker запускается без shell и без bind mounts;
- доверенный harness запускает решение в отдельном дочернем процессе на каждый тест, не передаёт ему ожидаемый результат и получает значение по отдельному бинарному каналу, поэтому debug-вывод не влияет на проверку;
- API принимает не более 12 000 символов и не более 8 запусков в минуту с одного IP; лимит применяется до аутентификации, поэтому случайные недействительные токены не позволяют обойти защиту backend.

Runner нельзя размещать внутри привилегированного API-контейнера или давать ему доступ к host-секретам. Для production Docker daemon должен быть вынесен на отдельный worker/узел с собственным лимитом параллелизма и мониторингом; текущее решение — безопасная граница MVP, а не multi-tenant sandbox общего назначения.

## Интервью-симуляция

Backend выбирает до пяти опубликованных вопросов и задач нужного направления и формирует сессию на 5–60 минут. `endsAt` принадлежит серверу: клиент не может продлить время, отправить ответ на чужой prompt или изменить завершённую сессию. Каждый ответ API содержит `serverNow`, поэтому countdown компенсирует расхождение системных часов и половину измеренного сетевого round trip. Активная сессия вместе с вычисленной поправкой кешируется на устройстве и восстанавливается после lifecycle-перехода. За пять секунд до границы клиент атомарно отправляет завершение вместе с текущим черновиком; если сервер уже закрыл сессию, текст остаётся в поле и показывается явное предупреждение.

Итоговый score детерминированно оценивает полноту и факт ответа. Он не проверяет техническую правильность и не является прогнозом найма — это явно показывается в результате. Следующий релизный этап может подключить редакторские рубрики или AI-review только после отдельного решения о privacy, стоимости и контроле качества.

## Данные пользователя

PostgreSQL хранит позицию видео, попытки квизов, до 50 последних решений на задачу и симуляции. Клиент показывает до 20 решений. Таблицы связаны с аккаунтом через `ON DELETE CASCADE`; экспорт аккаунта включает весь этот учебный прогресс, код и ответы. При удалении аккаунта локальный owner-кеш также очищается. Код решений и тексты ответов являются пользовательскими данными и не используются для аналитики без отдельного согласия.
