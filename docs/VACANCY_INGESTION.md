# Vacancy ingestion

## Принцип

Мобильный клиент никогда не парсит сайты вакансий. Отдельный backend получает данные только через официальные API, разрешённые feeds или оформленные партнёрские каналы. Для каждого источника проверяются правила использования, лимиты, требования к атрибуции и хранению.

Первый подключённый источник — бесплатный Job Board API Arbeitnow. Он не требует API-ключа, просит не злоупотреблять запросами и сохранять обратную ссылку. Backend запрашивает первую актуальную страницу не чаще одного раза в 15 минут, а приложение всегда показывает `Arbeitnow` и canonical URL карточки.

## Поток данных

```text
Arbeitnow adapter → Raw record → Normalizer → PostgreSQL/in-memory repository → Mobile API → AsyncStorage cache
```

Каждая нормализованная вакансия хранит:

- источник и внешний идентификатор;
- canonical URL оригинала;
- время публикации и время последнего получения;
- hash значимых полей для обнаружения изменений;
- provenance для преобразованных полей;
- срок хранения и статус удаления у источника.

## Дедупликация

Сначала используются точные ключи: источник + external id и canonical URL. Затем допускается осторожное вероятностное сопоставление по компании, должности, локации и текстовому fingerprint. Автоматически объединяются только записи выше высокого порога уверенности; остальные остаются раздельными.

## API клиента

```http
GET /v1/vacancies?query=react&specialty=Frontend&cursor=...
GET /v1/vacancies/:id
```

Ответ выдаётся cursor-страницами и содержит `syncedAt`, чтобы приложение явно показывало свежесть кеша. Удалённая у источника вакансия перестаёт попадать в выдачу, а сохранённая карточка помечается закрытой.

## Безопасность

- credentials источников находятся только в серверном secret storage;
- адаптеры имеют собственные rate limits, retry budget и circuit breaker;
- raw HTML не передаётся в мобильное приложение;
- описание очищается и нормализуется до безопасного текстового/структурного формата;
- все переходы ведут на allowlisted `https` URL источника.

## Ограничения этапа 1

- импортируется первая страница Arbeitnow; расширенный обход страниц и фоновые задания появятся после выбора инфраструктуры;
- in-memory режим теряет серверный кеш при перезапуске, PostgreSQL сохраняет вакансии и снимки;
- полнотекстовый поиск пока выполняется по нормализованным полям без отдельного поискового движка;
- HH API исследован, но не включён: из текущего окружения его DDoS-защита возвращает `403`; интеграция требует отдельной регистрации/проверки доступа и не должна обходить защиту.
