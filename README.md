# Interview Atlas

Мобильная платформа подготовки к техническим интервью для iOS и Android. Она объединяет учебные треки, актуализируемые вопросы, видеоразборы, практические задачи и вакансии из разрешённых источников.

## Что уже работает

- персональный экран «Сегодня» с направлением подготовки и серией занятий;
- учебные треки для Frontend, Backend, Mobile и QA;
- банк вопросов с коротким и развёрнутым ответом, тегами, датой обновления и источником;
- практические задачи с заготовкой кода, скрытым разбором и отметкой выполнения;
- нативное видео с продолжением просмотра, облачным прогрессом и проверочным тестом;
- безопасная проверка JavaScript-решений по скрытым тестам и история последних попыток;
- интервью-симуляция с серверным таймером, вопросами по направлению и итоговым разбором полноты ответов;
- web-CMS для вопросов, задач, видео и треков с версиями и редакционным workflow;
- опубликованный учебный контент загружается в приложение через API без выпуска новой сборки;
- живая лента вакансий Arbeitnow с серверным импортом, поиском, фильтрами и cursor pagination;
- локальный кеш вакансий, stale/error состояния, retry, pull-to-refresh и дозагрузка;
- сохранение вопросов и вакансий, локальный прогресс через Zustand + AsyncStorage;
- регистрация и вход по email, безопасная ротация сессий и отдельный экран аккаунта;
- облачная синхронизация направления, сохранённых материалов и решённых задач между устройствами;
- offline-очередь действий, статус синхронизации, экспорт данных и удаление аккаунта;
- onboarding по направлению, уровню, сроку, целевым компаниям и доступному времени;
- диагностическая карта из пяти навыков и выполнимый семидневный план теории, вопросов, практики и повторений;
- интервальные повторения: оценка сложности завершённой сессии обновляет слабые темы и пересчитывает остаток недели;
- локальные напоминания с quiet hours и deep link в конкретную сессию плана;
- сохранённые поиски вакансий с интервалом 6 часов, день или неделю и сгруппированными уведомлениями без повторов;
- объяснимый match score по направлению, уровню и навыкам, список конкретных пробелов и отдельный план под вакансию;
- статусы изменённых и закрытых сохранённых вакансий с последним известным снимком условий;
- корректное отображение при отсутствии сети и автоматическая светлая/тёмная тема;
- deep-link-ready маршруты `/question/:id`, `/task/:id`, `/video/:id`, `/simulation`, `/vacancy/:id`, `/vacancy-match/:id`, `/vacancy-searches` и `/preparation?session=:id`.

Боевой сбор выполняется только на backend через разрешённый публичный API. Мобильное приложение не содержит ключей, не скрейпит сайты напрямую и всегда сохраняет атрибуцию и ссылку на оригинал.

## Стек

- Expo SDK 57 + React Native + TypeScript;
- Expo Router;
- Zustand с AsyncStorage для несекретного локального прогресса;
- Expo SecureStore для refresh-сессии на iOS и Android; access-токен остаётся только в памяти;
- NetInfo для состояния сети;
- Expo Notifications для локальных напоминаний и перехода в запланированную сессию;
- Expo Video для нативного воспроизведения, полноэкранного режима и продолжения с позиции;
- нативные back-жесты, Android ripple и haptics.
- Fastify, Zod и PostgreSQL на backend;
- Arbeitnow Public Job Board API как первый живой источник.
- защищённая CSP и Bearer-токеном редакторская панель без отдельного frontend build-step.

## Запуск

Установите зависимости приложения и backend:

```bash
npm install
npm --prefix server install
```

Запустите backend без PostgreSQL — данные будут храниться в памяти:

```bash
npm run server:dev
```

В другом терминале запустите приложение:

```bash
npm run ios
```

Для Android используйте `npm run android`, для web-preview — `npm run web`. Web-export собирается как SPA, поэтому прямые ссылки на материалы, созданные в CMS после сборки, открываются без заранее известного ID; при самостоятельном хостинге все неизвестные пути должны переписываться на `index.html` (для Netlify/Cloudflare Pages правило уже находится в `public/_redirects`).

Для физического устройства скопируйте `.env.example` в `.env.local` и укажите LAN-адрес компьютера в `EXPO_PUBLIC_API_URL`. Android Emulator по умолчанию использует `http://10.0.2.2:4000`, iOS Simulator — `http://127.0.0.1:4000`.

Для постоянного хранилища скопируйте `server/.env.example` в `server/.env`, создайте базу и примените миграцию:

```bash
npm --prefix server run migrate
npm run server:dev
```

После запуска backend откройте `http://127.0.0.1:4000/admin`. Введите значение `CMS_ADMIN_TOKEN` из `server/.env`; токен хранится только в памяти вкладки и очищается при перезагрузке. Для CMS используйте PostgreSQL — in-memory режим предназначен только для локальной демонстрации и теряет материалы после перезапуска.

Аккаунт можно создать во вкладке «Аккаунт». Для проверки восстановления между устройствами backend должен работать с PostgreSQL. В web-preview refresh-сессия намеренно не сохраняется между перезагрузками вкладки; на iOS и Android она хранится в Keychain/Keystore через SecureStore.

После входа откройте «План подготовки» на экране «Сегодня» или во вкладке «Аккаунт». Разрешение на уведомления не запрашивается при запуске: системный диалог появляется только после явного включения напоминаний при настройке плана или сигналов сохранённого поиска. В web-preview планы и поиски доступны, но локальные системные уведомления отключены.

Видео открывается с вкладки «Учиться»: позиция сохраняется локально при уходе приложения в background и синхронизируется с аккаунтом. На вкладке «Практика» доступна интервью-симуляция. Для проверки JavaScript-решений заранее загрузите образ `docker pull node:24-alpine` и включите `CODE_RUNNER_ENABLED=true` в `server/.env`. Runner рассчитан только на синхронные JavaScript-функции и по умолчанию выключен. Полная модель и ограничения описаны в [docs/ADVANCED_LEARNING.md](docs/ADVANCED_LEARNING.md).

На вкладке «Вакансии» можно сохранить текущий запрос, выбрать частоту проверки и открыть объяснение совпадения из карточки вакансии. Score не является обещанием отклика: он детерминированно сравнивает профиль подготовки с нормализованными требованиями и показывает вклад каждого компонента.
